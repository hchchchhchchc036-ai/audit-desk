# AUDIT DESK

Windows 本地代码审计与软件测试桌面应用。黑底荧光绿终端界面，完整等宽字体、零圆角、系统监控与软件状态栏。

首次从 GitHub 下载源码，请先阅读[中文运行文档](docs/运行文档.md)。仓库不包含模型密钥、个人配置、真实项目报告或安装包。

## 启动

每次启动回到默认首页，不自动载入上次项目索引、架构图或历史任务流程。模型配置、项目列表、独立上下文和历史报告继续保留；选择已保存项目会重新索引，工作流程在本次启动任务后更新。

双击根目录的 `启动应用.cmd`，或打开 `release/0.1.10/win-unpacked/Audit Desk.exe`。安装版为 `release/0.1.10/Audit Desk Setup 0.1.10.exe`，安装后可从桌面快捷方式启动。安装包未使用商业代码签名证书。

1. 在“模型与报告”填写协议、Base URL、模型名称和 API Key，保存并测试连接。支持 OpenAI Chat Completions 兼容服务和 Anthropic Messages。
2. 选择本地项目文件夹；等待索引完成，检查文件、模块和排除原因。中文路径与带空格路径已验证。
3. 在“代码审计”选择单模块、多模块或整个项目及审计引擎。软件显示模型地址与发送范围，确认后运行。
4. 在“软件测试”选择类型，复用项目现有命令或让模型生成测试。命令格式为 JSON 参数数组，例如 `["node", "--test", "tests/auth.test.js"]`。
5. 查看任务日志、证据与报告；默认导出中文 Word（.docx），也可打开中文 HTML、Markdown 或导出完整证据包。

## 中文报告

Word、Markdown 和 HTML 共用中文正文，审计报告列出问题位置、原因、源码中的依赖引用、入口到关键操作的问题链、修改建议和复测方法；缺乏证据的关系标为待验证，不推定依赖存在漏洞。测试报告列出实际测试目标、命令、用例与结果，通过写“正常”，失败写明问题，未执行或部分完成不写正常。

JSON 保留原有字段、类型和状态值，便于程序读取。代码、文件路径、包名、运行器用例标识和原始日志保留原文。安全审计附属 Markdown 也使用中文说明。

旧报告在打开或导出时，使用当前配置的模型翻译英文分析文字；不会重新运行项目代码或更改原始 JSON、证据与问题状态。翻译用量计入所属项目，译文缓存后复用。没有配置可用模型时，英文历史报告需先补全模型配置；新报告默认要求模型以中文生成。

## 审计与模型

`security-audit` 为应用内审计工作流，执行源码侦察、覆盖分配、审计、独立复核、结构校验和报告。静态源码可以证明的边界问题与需要运行环境验证的问题分别记录。模型有误判可能；最终报告保留原始证据与未完成原因。

覆盖标识包含文件位置，避免不同文件的同名边界冲突。审查中新发现或规则发生变化的边界，会在原文件完整审查后自动尝试一次完整源码补审；必需规则缺失、预算不足、源码超出单次输入上限或补审后再次变化的边界仍保留待补审，不能直接计为覆盖。所有验证调用统一按接口实际返回用量结算；无 usage 时使用明确标注的估算。

Open Code Review 使用本机 `ocr scan` 全文件模式。程序自动发现已有 OCR；未安装时首次使用会下载 Alibaba 官方 Windows 发行文件，校验发行 SHA256 后安装到应用数据目录。OCR 直接共用软件中的模型设置，不需要再次配置 Provider。每次任务使用独立环境，不覆盖用户原有 OCR 设置。

OCR 扫描索引时建立的只读内容副本，先执行无模型预览，确认存在可审查文件。密钥不放进命令参数，不写入报告；Windows 用户级加密存储模型配置。任务运行固定开始时的模型地址、名称和密钥；最大输出 token 修改并保存后，从下一次内置模型请求同步生效。

## Skill 库

已完整下载并随应用安装：`security-audit`、`open-code-review`、`semgrep`、`webapp-testing`、`test-driven-development`。来源、commit、哈希、星数快照和许可证在 `skills/manifest.json` 及各 Skill 的 `SOURCE.json` 中。关联规范、脚本和许可证文件保留在 Skill 目录。

用户可以从完整本地目录、单独 `SKILL.md` 或 GitHub 仓库的具体目录导入，也可以编辑应用内副本、启停、移除并为任务选择附加 Skill。GitHub 表单的仓库字段使用 `owner/repository`，路径使用 `skills/example`，分支可以留空。导入不会执行脚本。

Skill 是规则和参考材料，执行工具另行受限。Bash 专用脚本、Semgrep、CodeQL 或某项目的专有测试依赖不会因为存在 SKILL.md 就自动可运行。应用保留完整内容，模型按预算载入或总结，并在报告披露相关覆盖缺口。

## 测试环境

测试类型可多选，提供全选与清空；所选类型绑定同一项目上下文，按队列分别运行、分别生成报告。模型生成时按每种类型制定计划；手填命令则每种类型复用该命令，性能类型仍要求真实性能指标，不能仅凭普通单元测试通过判定性能正常。

某一测试失败不会阻止下一项排队测试。结果解析检查整段运行输出，后续失败记录不能被较早的成功 JSON 汇总覆盖。性能请求错误率大于零时判为失败，即使延迟未超过阈值。测试计数、负载指标或截图证据不足时，报告列明实际缺少项，保留部分完成状态。

任务中的模型 API 请求超时后最多自动重试 2 次，每次等待上限分别为配置值、配置值的 2 倍和 3 倍（单次最多 1800 秒），每次调用显示独立记录。用户取消、认证失败和其他非超时错误不会自动重试；重试仍受任务总时限约束。超时请求在服务端可能产生费用，但未返回的用量无法确认。

应用数据磁盘剩余不足 64 MiB 时会阻止新任务和报告生成，避免模型运行后才发现无法保存；需要先释放应用数据所在磁盘空间。磁盘空间不足不会通过自动删除项目或报告解决。

默认测试和自定义工具在本地项目副本执行，无需启动或安装 Docker。Node 测试复用软件内置 Node 运行时；npm、Python、浏览器等需要本机具备相应运行器和依赖。程序不自动安装项目依赖。开始本地执行前界面确认当前用户权限：普通本地进程可访问本机文件和网络，不是安全沙箱；不可信代码应选择 Docker 模式。

“模型与报告 → 测试 / 工具执行方式”可切换为 Docker。仅此模式检测 Docker 和镜像，并使用无外网、资源受限、只读源副本的容器。默认本地模式不会调用 Docker。工具或证据不足时如实显示未执行、失败或部分完成，不把空测试算作通过。

性能报告要求实际请求数、并发、持续时间、吞吐量、错误率、P50/P95/P99 和阈值比较。自动化执行支持有界截图与日志证据；导出报告保留产物引用。

## 实时状态

顶栏显示软件名称、系统联网状态、电量/充电状态与本机时间。无电池的台式机显示 AC / 无电池；未知状态显示 `--`。联网状态表示操作系统检测结果，不保证具体模型服务可访问。

“工作流程”默认保留三步使用说明。开始审计或测试后自动切换为实时流程图，显示当前阶段、已完成节点与实际调用记录。模型 API、OCR CLI 和 Docker 执行分别记录开始、结束、耗时、命令与结果；任务结束保留轨迹。OCR 未公开的内部逐次工具调用明确标为未提供。

SYSTEM_MONITOR 每 2 秒采样整机 CPU/各核心/内存与应用占用，显示任务与文件完成读数。Token 优先使用模型接口返回的实际输入、输出用量；没有 usage 时明确标注估算。分别显示最近一次请求输入与本地项目记忆估算，不声称能读取模型服务内部记忆。OCR CLI 未提供用量的任务单独标注。用量按项目持久保存，任务用量同时保存在报告中。

## 项目与上下文管理

项目管理可导入、切换或移除项目列表项，保留源文件和历史记录。每个项目使用独立上下文；运行中的任务固定绑定启动时的项目、模型身份与上下文，切换页面不会改变任务目标；最大输出 token 保存后同步到后续内置模型请求。模型配置提供 8K–2M 上下文容量，其中 1M=1,000,000 token，并同步监控显示。模型服务本身需要支持所选容量。

“上下文”窗口提供压缩、重置和打开交接文档。压缩保留摘要与近期记录；重置先保存 HANDOFF.md，再创建新上下文并导入交接。原始记录归档，失败时保留当前上下文。同项目任务执行期间禁止压缩和重置。

“Skill 与工具”支持注册、编辑和启停自定义 argv 工具，可手动运行，也可在任务中勾选交给模型选择。命令使用所选执行方式，默认本地项目副本、可选 Docker，结果记录到对应项目；不提供用户对话窗口。项目与上下文流程详见 `docs/context-and-projects.md`。

## 开发与验证

要求 Node.js 22.12 或更高版本。`npm.cmd install` 安装依赖；`npm.cmd start` 启动开发版本；`npm.cmd test` 执行核心检查；`npm.cmd run test:ui` 检查真实 Electron 页面；`node scripts/live-docker-check.cjs` 执行真实隔离测试；`npm.cmd run dist` 在 `release/0.1.10/` 生成 Windows 安装包，启动脚本优先使用该目录中的新版程序。

UI 验证使用本地确定性模型协议夹具，不调用付费模型。真实服务的分析效果需在用户配置模型后验证。安装包与启动版包含相同代码和五个 Skill；应用数据默认位于 Windows 用户的 Electron 应用数据目录，开发自动化检查使用独立 `.runtime` 数据目录。

架构与流程见 `docs/design.md`；应用自测记录见 `docs/SELF-TEST.md`。实际 UI 截图与容器测试报告保存在 `artifacts/`。
