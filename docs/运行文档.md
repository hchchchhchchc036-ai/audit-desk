# Audit Desk 运行文档

## 环境要求

- Windows 10/11。
- 从源码运行或构建：Node.js 22.12 或更高版本，包含 npm。
- 测试 Python、npm 或浏览器项目时，本机须安装对应运行器和项目依赖。
- 默认本地执行，无需 Docker；仅选择 Docker 隔离模式时需要 Docker Desktop。

## 从源码启动

在项目根目录打开 PowerShell，按顺序执行：

```powershell
npm.cmd ci
npm.cmd start
```

首次安装会下载 Electron。不要把 API Key 写入源码或 `.env` 后提交；在应用的“模型与报告”页面保存。

## 第一次使用

1. 在“模型与报告”选择协议，填写 Base URL、模型名称和 API Key，保存并测试连接。上下文容量须与实际模型能力一致。
2. 导入项目文件夹，等待索引，检查文件范围和排除原因。
3. 在“代码审计”选择单模块、多模块或整个项目及审计引擎，确认发送范围后运行。
4. 在“软件测试”勾选测试类型；填写 JSON 命令参数数组，或使用模型生成测试。先安装待测项目所需的依赖。
5. 查看真实执行日志与结果，导出中文 Word、HTML、Markdown 或 JSON；失败、待验证和部分完成均保留原状态。

手填测试命令示例（请替换为待测项目实际命令）：

```json
["node", "--test", "tests/auth.test.js"]
```

本地模式使用当前用户权限执行代码，可访问本机文件和网络；不可信项目应选择 Docker 隔离模式。配置远程模型后，所选源码会发送到对应服务，须确认你有权发送这些内容。

## 检查与打包

```powershell
# 构建并执行核心测试，不使用你的付费模型。
npm.cmd test

# 桌面界面检查：使用本地模型协议夹具。
npm.cmd run test:ui

# 生成 Windows 安装包。
npm.cmd run dist
```

当前版本安装包生成于 `release/0.1.10/`。若 Electron 已安装但构建时再次下载失败，可执行：

```powershell
npm.cmd run dist -- --config.electronDist=node_modules/electron/dist
```

完成构建后可运行 `release/0.1.10/win-unpacked/Audit Desk.exe`，或安装 `Audit Desk Setup 0.1.10.exe`。根目录 `启动应用.cmd` 优先启动已构建的版本；源码启动以 `npm.cmd start` 为准。

## 配置与数据保护

应用配置和项目上下文默认保存在 Windows 用户应用数据目录 `%APPDATA%/Audit Desk`，API Key 使用 Electron safeStorage 加密。不要上传整个用户数据目录，密钥加密文件也不应提交或跨电脑复制。

仓库仅包含源码、测试、中文文档与随应用分发的 Skill；忽略模型设置、项目上下文、真实项目报告、截图日志、临时文件、依赖目录和安装包。第三方 Skill 的来源和许可证见 `skills/manifest.json`、各目录的 `SOURCE.json` 与许可证文件。

提交前运行以下检查；检查只报告文件名和行号，不打印匹配的凭据内容：

```powershell
git add .
node scripts/check-publish.cjs
git diff --cached --stat
```

检查通过后再提交。不要使用 `git add -f` 强行加入被忽略的配置或证据文件。

## 常见问题

- HTTP 401：在应用里更新 API Key 并重新测试连接，不要把密钥贴到 issue 或日志中。
- 超时：检查模型服务、网络及超时设置。已取消或部分完成的内置源码审计可在任务卡片继续；源码、模型、上下文或规则变化时重新运行。
- 磁盘不足：释放应用数据所在磁盘空间后重试。程序不会自动删除项目或历史报告。
- 缺少 Python、npm 或浏览器：安装对应运行器和项目依赖，再启动测试；没有执行成功的测试不会计为正常。
- Open Code Review 首次使用：需要联网下载并校验官方程序，随后复用应用模型配置。
